```text
ЗАДАЧА: статический сайт-каталог Beauty Supply (Москва, RUB, русский язык).

ИСТОЧНИКИ ДАННЫХ (только они; ничего не выдумывать):
1. Бриф BEAUTY_SUPPLY_SITE_BRIEF.md v1.0 (приложен) — 10 товаров в наличии
   BS-001…BS-010 с ценами и Avito-ссылками.
2. https://aifirsts.github.io/MATRIX2/index.html#catalogue — блок «пополнение
   склада в Москве от 28.10.2026» (цены из переписки с продавцом).
3. https://t.me/beautysupply_ru — Telegram для заказов (подтверждён владельцем).

ШАГ 0 — СВЕРКА ДАННЫХ (до написания кода):
- Открой MATRIX2 и сверь список BS-001…BS-010 с текущим каталогом источника.
- Из блока 28.10.2026 возьми beauty-товары. НОВЫЕ позиции → предзаказ.
  ПОЗИЦИИ, ДУБЛИРУЮЩИЕ товары в наличии, → не создавай отдельную карточку,
  а обнови цену соответствующего in_stock-товара (старую цену зафиксируй
  в поле price_note).
- Заполни поля TBD из MATRIX2, если данные там есть (бренды BS-007/BS-008 —
  IMAGE Skincare и т.п.).
- Если источник недоступен — оставь товар со статусом hidden, не выдумывай.
- Запрещены к публикации: часы, чехлы, палетка Hourglass за 6 000 ₽
  (Charlotte Tilbury Pillow Talk за 6 000 ₽ остаётся — это тени, не та палетка).
- Итоговый каталог: 10 в наличии + сколько подтверждено предзаказов (0–5).
  Карточки с TBD, нулевой ценой или «Предзаказ №N» публиковать нельзя.

ШАГ 1 — ФАЙЛЫ (работать только по этому списку):
- index.html — одна страница: header, hero, преимущества, две секции каталога,
  «Как заказать», FAQ (12 вопросов), footer с дисклеймером.
- styles.css — mobile-first от 320 px, без внешних шрифтов/CDN/библиотек.
- app.js — в начале файла константа const TELEGRAM_URL = 'https://t.me/beautysupply_ru';
  (единственная точка настройки Telegram). Загрузка data/products.json через fetch,
  отрисовка секций, скелетоны загрузки, обработка ошибок, экранирование HTML.
- data/products.json — каталог. URL — обычные строки (не Markdown). Схема товара:
  id, title, brand, category, price_rub, status (in_stock|preorder|hidden|sold),
  city, short_description, photos, source, source_url, stock (null если остаток
  неизвестен), preorder_note, price_note (опционально), updated_at.
- assets/README.md — как добавлять фото (photos[0] показывается в карточке;
  без фото — заглушка с брендом, никаких выдуманных фото).
- docs/SITE_SPEC.md — спецификация, правила обновления каталога, решения по данным.
- docs/PROMPT_AUDIT.md, docs/IMPROVED_PROMPT.md — аудит и этот промпт.
- README.md — краткое описание проекта и ссылка на docs/.

ШАГ 2 — ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ:
- HTML/CSS/JS без React, Vue, Tailwind, Bootstrap, jQuery и внешних CDN.
- Секции витрины определяются полем status; category — атрибут товара.
- Товары hidden/sold не отображаются.
- Кнопки Telegram: hero, шапка, каждая карточка, footer. В карточке — ссылка
  с автотекстом «Здравствуйте! Хочу заказать товар BS-XXX — Название.»
- SEO: title, meta description, Open Graph (og:title, og:description, og:type,
  og:locale ru_RU).
- Семантический HTML, доступность: skip-link, aria, фокус, контраст WCAG AA,
  touch-таргеты от 44 px.
- Никаких корзин, оплаты, личных кабинетов, backend.
- Локальная проверка через HTTP-сервер (python3 -m http.server), не file://.

ШАГ 3 — QA (обязательный):
- Скриншоты на 320, 375, 768, 1280 px: без переполнений, переносов и обрезок.
- Проверить: 10 товаров «В наличии», N предзаказов, отсутствие excluded-товаров,
  работу Telegram-кнопок, состояние ошибки (переименуй products.json и верни),
  валидность JSON.

ШАГ 4 — РЕПОЗИТОРИЙ И ПУБЛИКАЦИЯ:
- Новый приватный репозиторий GitHub (без авто-README и начального коммита).
- Один финальный commit: "feat: Beauty Supply static catalog with in-stock and
  preorder sections".
- Сайт задеплоить на хостинг превью Perplexity Computer (deploy_website).
  GitHub Pages как боевой хостинг не использовать.
- В README указать ссылку на превью и инструкцию локального запуска.

ЗАПРЕЩЁННЫЕ ФОРМУЛИРОВКИ НА САЙТЕ: «100% оригинал», «гарантия»,
«беспошлинный ввоз», «гарантированная доставка», «лучшая цена»,
«возврат без условий».

ЭКОНОМИЯ РЕСУРСОВ: без лишних web-исследований (только MATRIX2 и бриф),
без черновиков, работа по списку файлов, один коммит.

ФИНАЛЬНЫЙ ОТЧЁТ (единый формат):

NEXT_STEP: [один конкретный шаг]
```
